# LocalWhale v0.1.4 — Version-agnostic update allowlist & dsh-ecosystem-spec plugin admission / 去版本化更新白名单与 dsh 生态规范插件准入

Release date / 发布日期：2026-09-01

LocalWhale 0.1.4 makes the Harness update pipeline resilient to future upstream releases and adds dsh plugin ecosystem compatibility checks around Harness updates. The bundled initial runtime remains DeepSeek Harness `0.1.0-rc.6`, Node.js `24.18.1`, and pnpm `11.7.0`.

LocalWhale 0.1.4 让 Harness 更新管线对未来上游发版更具弹性，并围绕 Harness 更新加入 dsh 插件生态兼容性检查。随包初始运行时仍为 DeepSeek Harness `0.1.0-rc.6`、Node.js `24.18.1` 与 pnpm `11.7.0`。

## Fixed / 修复

- Updating to Harness `0.1.1-rc.2` failed with `Candidate runtime contains unapproved lifecycle scripts: @deepseek-ai/dsh-subprocess-local@0.1.1-rc.2:postinstall, koffi@3.1.6:install, protobufjs@7.6.6:postinstall`. All three script bodies are byte-identical to already-approved entries; they were rejected on version alone.
- 更新到 Harness `0.1.1-rc.2` 时报 `Candidate runtime contains unapproved lifecycle scripts`，涉及 `dsh-subprocess-local@0.1.1-rc.2:postinstall`、`koffi@3.1.6:install`、`protobufjs@7.6.6:postinstall`。三个脚本体与已批准条目逐字节一致，仅因版本号被拒。

## Changed / 变更

- The supply-chain lifecycle-script allowlist no longer pins package versions: an entry now matches package name, script name, and script-body SHA-256. Future Harness releases whose dependencies only bump versions install without a LocalWhale release; any dependency that edits or introduces a lifecycle script is still rejected until reviewed.
- 供应链生命周期脚本白名单不再绑定包版本号：条目按包名 + 脚本名 + 脚本体 SHA-256 匹配。今后依赖仅升版本号的 Harness 版本可直接安装，无需先发 LocalWhale；任何修改或新增脚本的依赖仍会被拒绝，直至人工复审。
- LocalWhale now implements the [dsh-ecosystem-spec](https://github.com/T-Auto/dsh-ecosystem-spec) (DSH Community Ecosystem Interoperability Specification, baseline 0.15) plugin admission model: `dsh-plugin.json` manifests under `.dsh`/`DSH_HOME` are evaluated whenever a Harness update is discovered or validated, using the five admission states (compatible / compatible-degraded / waiting-authorization / rejected / unknown). Results are logged per plugin and summarized on the update card; evaluation reads manifest files only and never blocks an update. The spec text is vendored under `third-party/dsh-ecosystem-spec/` (MIT).
- LocalWhale 实现了 [dsh-ecosystem-spec](https://github.com/T-Auto/dsh-ecosystem-spec)（DSH 社区生态互操作规范，基线 0.15）的插件准入模型：发现或验证 Harness 更新时，会评估 `.dsh`/`DSH_HOME` 下的 `dsh-plugin.json` 清单，按五种准入状态（兼容 / 降级运行 / 需授权 / 不兼容 / 无法判定）报告。结果逐插件写入日志并在更新卡片汇总显示；评估只读取清单文件，且永不阻断更新。规范文本以 MIT 许可引入 `third-party/dsh-ecosystem-spec/`。
- Plugin developers get cross-version compatibility verdicts by shipping a spec-compliant manifest (`manifestVersion: "0.15"`, `facets.host.apiVersion`, `requires.contracts` with `fallback` on optional entries). LocalWhale maps each Harness version to the contract coordinates it mediates via `HarnessContractProfile`; unregistered future Harness versions fall back to the newest known profile so plugin evaluation never blocks on an unregistered release.
- 插件开发者只需提供符合规范的清单（`manifestVersion: "0.15"`、`facets.host.apiVersion`、`requires.contracts`，可选条目附 `fallback`）即可获得跨版本兼容判定。LocalWhale 通过 `HarnessContractProfile` 把每个 Harness 版本映射到其向插件暴露的契约坐标；未登记的未来 Harness 版本回退到最新已知适配，评估不因未登记而阻塞。

## Upgrade safety / 升级安全

- Settings, staged updates, `%USERPROFILE%\.dsh`, and the official Harness WebUI remain untouched. Plugin admission reads `dsh-plugin.json` files only.
- 设置、暂存更新、`%USERPROFILE%\.dsh` 与官方 Harness WebUI 均不受影响。插件准入只读取 `dsh-plugin.json` 文件。
- The allowlist still matches script bodies byte-for-byte; the security boundary is unchanged — only the version dimension was removed.
- 白名单仍按脚本体逐字节匹配，安全边界不变——仅移除了版本维度。

## Known limits / 已知限制

- Windows 11 x64 only; no Windows 10, ARM64, Store, or cross-platform package.
- 仅支持 Windows 11 x64；不提供 Windows 10、ARM64、Microsoft Store 或跨平台版本。
- The installer remains unsigned and can show an unknown-publisher warning.
- 安装器仍未签名，Windows 可能显示“未知发布者”警告。
